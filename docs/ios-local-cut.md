# BeatVision iOS — Local Cut (no provider billing)

**Status:** iOS source integration; Xcode and signed device build NOT VERIFIED.

## What this does

This retains BeatVision's existing React/Vite app, Supabase auth, owner-scoped reads, Vision Lock, song/World/Style/Scene flows, and the generation controller's zero-cost guard. It does **not** make a new backend or bypass provider cost checks.

The new `/projects/:projectId/local-cut?plan=:approvedPlanId` view:
- Reads approved scene boundaries only through existing Supabase owner-scoped queries.
- Imports a matching audio file and user-owned still images or video clips **locally**. It never uploads these local files or writes creative state.
- Uses the approved scene timeline to preview the images/clips against the song.
- When all scenes use still images and the browser supports `canvas.captureStream` and `MediaRecorder`, encodes a 720p real-time local animatic with original audio. No paid AI or remote assembly service is used.
- Rejects a mismatched duration, timeline gap/overlap or unsupported encoding, instead of falsely reporting success.
- Explicitly does not claim to generate AI pictures or motion, persist approved assets, or replace final_videos.

**Limitations:** Imported video clips are preview-only. A local video export may not be supported by every iOS WKWebView/codec. The browser's download link may need a native Files/share extension for reliable saving on iOS. The render runs in real time and must remain in foreground. Long song processing, low-memory devices and browser audio synchronization remain unverified. This is not yet a durable provider-free production final-video pipeline.

## Add the real iOS platform (requires a Mac + Xcode)

```bash
npm install
npm run build
npx cap add ios
npx cap sync ios
npx cap open ios
```

Build and run the `App` target in Xcode on a simulator and a physical iPhone; verify authentication, approved plan access, local file picker, preview, the actual encoded video bytes, Files export and background/interruption behavior before TestFlight. Capacitor 8 requires a supported Xcode toolchain. Confirm current requirements from the official Capacitor docs.

Do not check generated signing material or developer credentials into Git. The `ios/` native project is generated by `cap add ios`. It was compiled successfully on a hosted macOS GitHub Actions runner; it has not been checked into the repository. The app bundle identifier in `capacitor.config.ts` must be checked in Apple Developer provisioning before App Store submission.

## Security and approval invariants

- New remote scene-image generation still stops with `PROVIDER_COST_UNVERIFIED`. Current main treats stage-only assembly separately. Local Cut invokes neither and does not alter either controller path.
- No project, audio, approvals, asset rows, `generation_jobs`, RLS, storage or migrations are modified by Local Cut.
- Local export is an unapproved **manual animatic**, not a canonical `final_videos` row; it cannot be used to bypass owner or Vision Lock checks.
- Native iPhoneOS compilation passed on a hosted macOS runner. No physical-device signing or test, local export on an actual iPhone, paid provider call, migration or production deployment was performed.

## Smoke test sequence

1. Sign in with existing account.
2. Open a project with an approved Visual Plan and verify the correct plan ID/scenes.
3. Open Production Workspace → Local Cut.
4. Select the exact song and an image for each scene.
5. Preview all scene boundaries with the timeline.
6. Export locally if the codec and capture APIs are supported.
7. Verify decoded bytes and audio/video duration, not just a nonempty Blob.
8. Verify mismatch, unsupported codec, unauthorized project and imported-video fallback errors.


## Sign an installable iOS Ad Hoc IPA

The automated native compilation passed on [GitHub Actions run 39099109906](https://github.com/DaddyDom8249/BeatVision/actions/runs/39099109906). That artifact is **unsigned** and will not install on an iPhone.

The separate [secure signing workflow](../.github/workflows/ios-sign-ad-hoc.yml) builds a **signed Ad Hoc** IPA only when an Apple Distribution identity and valid provisioning profile are available. It validates the profile expiry, bundle ID, registered devices, and final embedded signature. No certificates or passwords belong in the repository or in chat.

1. In your Apple Developer Program account, register an App ID with bundle identifier `com.beatvision.studio`, create an **Apple Distribution** certificate with its private key, and register the UDID(s) of iPhone(s) that will install the app.
2. Create an **Ad Hoc** iOS provisioning profile for that App ID, distribution certificate and registered devices. Export the certificate **including its private key** to a password-protected `.p12` file. Download the `.mobileprovision` file.
3. Under [GitHub Actions secrets](https://github.com/DaddyDom8249/BeatVision/settings/secrets/actions), add these **repository secrets**, never committed files:
   - `APPLE_SIGNING_P12_BASE64`: the base64 representation of the entire `.p12` file, as one line.
   - `APPLE_SIGNING_P12_PASSWORD`: the password protecting that `.p12` file.
   - `APPLE_ADHOC_PROFILE_BASE64`: the base64 representation of the entire `.mobileprovision` file, as one line.
4. On macOS, `base64 -i certificate.p12 | tr -d '\n'` and `base64 -i profile.mobileprovision | tr -d '\n'` can prepare the two secret values locally. Do **not** put signing assets in issues, logs, ChatGPT, PR descriptions or Git commits.
5. After adding all three secrets, rerun [the gated signing workflow](https://github.com/DaddyDom8249/BeatVision/actions/workflows/ios-sign-ad-hoc.yml) on branch `feature/ios-local-cut-20261017`, or rerun the failed signing job. On success download artifact `BeatVision-iOS-SIGNED-AdHoc` (contains `BeatVision-SIGNED-AdHoc.ipa`). Installation works only on devices included in the Ad Hoc profile.

**Strict $0 alternative:** An Apple Account without paid program membership can use an Xcode **Personal Team** to sign and install a development build directly on a locally connected personal iPhone. Apple's personal-team provisioning profiles expire after seven days and require repeated builds. This does **not** provide portable Ad Hoc/TestFlight distribution from the GitHub runner. If you do not have a paid Apple Developer Program membership, the Ad Hoc workflow cannot complete with a legitimate distribution certificate and Ad Hoc profile.

**Evidence:** [First signing attempt](https://github.com/DaddyDom8249/BeatVision/actions/runs/39100183727) stopped at its missing-credentials gate. It did not produce a signed IPA. Keep original unsigned artifacts clearly labeled, and do not rename them as signed.
