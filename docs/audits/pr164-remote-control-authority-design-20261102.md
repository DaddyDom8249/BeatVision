## Trusted-authorizer contract

An eventual issuer must independently establish all of the following. Locally
supplied references, template fields, booleans and environment variables cannot
bootstrap trust. Even a valid signature over a claim does not prove the underlying
account limit, isolation or deployment state exists.

| Evidence domain | Required independent checks |
| --- | --- |
| Owner authority | Authenticated owner and correct `projects.owner_id`; exact frozen manifest digest; separate deploy, request/campaign, fault and teardown purposes; revocation and expiration. A deploy token cannot authorize task termination. |
| Account/workspace and cost | Actual intended identity, verified credit eligibility, provider-enforced zero paid overage and a budget reserved for this exact campaign. Available credit, published pricing, alerts, max containers and TTL are insufficient. Missing enforcement means BLOCKED. |
| Deployment | Actual origin→deployment revision→App→Function→source/image chain; explicit staging environment; CPU-only package; intended limits and exclusive input. A user header, `ta-*` string, environment SHA or App ID alone is insufficient. |
| Database/fixtures | Dedicated non-production identity/run, owner, RLS, retained admission history, tested consistent restoration, disabled automations/old execution paths, explicitly approved synthetic source, immutable snapshot and provenance hashes. No approvals or job state may be reset to satisfy these checks. |
| Access | Independently enforced exact task/App/Function permissions, bounded actions and expiration. Reject wildcard/account-wide control as a substitute for a narrowly scoped campaign credential. No shell/exec or arbitrary task selector. |

Authenticated adapters must verify issuer/key provenance, expected audience and
subject, challenge/action/job/manifest binding, current revocation, observation
freshness and expiry. A fresh challenge must be generated by the verifier. Do not
accept caller-supplied witness content as an independent observation. Actual trust
roots, authenticated transports, key rotation/revocation and no-overage adapters
are **NOT IMPLEMENTED/NOT VERIFIED** here.

The frozen manifest binds owner/account/workspace, environment, deployment/App/
Function, source commit, image, exact HTTPS origin, database/run, prepared job/
request/snapshot/provenance hashes, request/control caps and deadlines. Missing,
empty or incorrectly typed identities are rejected. A changed manifest requires
a new independently reviewed campaign; changing a run's digest cannot reset its
retained budget. A new run cannot reclaim the same unresolved task incarnation.

Before issuing any future permit, atomically debit an independent retained
request ledger across clients/workers. Request UUIDs are consumed once; failures,
revocation after debit and lost replies do not refund/reissue them. Recheck
authority after a slow durable reservation. Dispatch still needs bounded trusted
transport and server-side expiry enforcement; a local observation check does not
make the later remote effect atomic. The existing client's process budget is not
a distributed authorization service or account spending cap.

## Remote fault protocol proposal

1. Independently authorize a single prepared job/boundary. Record an immutable
   operation intent in an isolated control ledger, separate from generation
   admission. It must never enqueue inference or rewrite creative input/approval.
2. Arm a private authenticated staging checkpoint with run/job/request, nonce,
   expected row version, source/provenance and exact task incarnation. The stage
   worker must commit its boundary evidence and remain paused until death;
   timeout/disconnect must fail closed rather than resume execution. No public
   crash/reset API or worker-held account control credential is proposed.
3. Independently corroborate task→input→Function→App revision/image→environment→
   workspace/account and exact task-scoped permission. Observe the private DB
   checkpoint separately from provider metadata. Bind known receipts and execution
   fence, not just job-shaped strings. Reject stale/replayed witnesses or any
   changed row version before control dispatch.
4. Durably reserve a one-shot operation **before** remote action. Retain a global
   task/incarnation fence across campaign IDs, a run budget and a unique pause
   nonce. Competing controllers cannot independently send another stop. Crash
   before dispatch, lost acknowledgment or persistence refusal leaves a permanent
   `STOP_UNKNOWN` hold; no retry, replacement task or inference is authorized.
5. The remote mechanism must provide conditional identity/input binding, or an
   independently guaranteed immutable target/pause until termination, plus safe
   stop semantics. This is **unresolved**. Fresh client-side checks and another
   database flag do not solve the final observation→provider-effect race. The
   inspected SDK method supplies no such predicate. No real adapter is shipped.
6. A stop acknowledgment remains unknown. Require independent termination/input
   evidence, explicit no-rescheduling/replacement evidence and settled private
   database before/after evidence. Preserve input/provenance, known receipts,
   execution fence and event counts. A contradictory running observation or
   changed output/receipt cannot reaffirm a previously verified observation.
7. Check every collected proof deadline and the authority window immediately
   before action/persistence. Persist the whitelisted termination and before/after
   evidence with the state change; reject/roll back expired or failed writes.
   Retained unknown claims must survive controller/process death and DB outages.
8. Allow separately authorized read-only observation after the control deadline.
   It cannot renew the worker window, send another stop, resubmit inference or
   modify jobs. Teardown remains a distinct owner-authorized operation with actual
   provider/account termination evidence; expiry is not billing teardown.

The model can reopen a retained manifest after controller restart only through
an explicitly observation-only policy within its original observation window.
That mode rejects POST, GET, control, deploy and teardown decisions; it reads
existing independent evidence without extending either deadline or claim.

## Executable model and explicit limits

`providers/modal_motion/tests/staging_control_model.py` is a **test-only model**.
Its five `MockWitness` domains, `MockCheckpointStore`, `MockRemote`, proof key IDs,
clocks and provider capability assertions are fixtures. It performs **no signature
verification, real identity lookup, billing check, remote kill or provider call**.
Its hypothetical `abrupt_no_reschedule` capability and rich termination evidence
are not asserted to exist in Modal. Actual SIGINT/rescheduling and graceful
semantics are rejected. This is not a production trust boundary or security
sandbox: code with local fixture access can change the fake authorities.

`ModelDecision` is deliberately not `LivePermit`; even a positive fixture decision
is rejected by the real HTTP client. No production runtime/package/CLI imports the model,
no live issuer is configured, and the seven-file CPU deployment package is
unchanged. No actual control endpoint or checkpoint schema has been added.

Disposable SQLite models atomic request/control admission and retained global
task fences. It is not a production control ledger or PostgreSQL/RLS proof.
Eight independent CPU controller processes append exactly one fake provider
attempt; append-only evidence counts every call. Actual local process exits42
before/after fake dispatch leave retained holds. Those exits are not remote
container evidence. The model's clock rollback detector is per instance, not a
distributed trusted clock. Real deployments need authoritative time, retained
state and enforcement at the actual action boundary.

The negative check-then-stop oracle deliberately changes the mocked active input
after the last client-side check. A fake stop is still sent; the model refuses to
verify it and retains `STOP_UNKNOWN`. **This is an unsafe counterexample**, not
a successful crash case. It demonstrates why the live atomic-targeting gate
remains BLOCKED despite passing model tests. No exactly-once guarantee follows.

Independent source review identified model-only freshness, empty-identity and
cross-run replay defects. Executed regressions reproduced33failed subcases and
passed after repair; the reviewer confirmed the source changes without running
tests. Production lifecycle behavior was not changed or claimed fixed by them.
